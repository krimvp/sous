Local agent orchestration

Murmuration

Give it a goal. A flock of agents splits it, builds it, merges it and checks it, until it is done.

Lead agents plan and delegate. Claude Code, Codex and Pi do the work, each in its own git worktree. Plain code keeps everything moving, merges every branch, and picks up where it stopped after a crash. It runs on your machine, from your terminal.

# in the repository the agents should work in
$ murm run "Add a --precision N option to the CLI, with tests"
$ murm status                       # the live tree, from another terminal
$ murm answer lead "Round half up."  # reply to a question, or steer a lead

How a goal becomes finished work

One goal in, one branch out

  1. A lead takes the goal

    It writes shared notes (interfaces, conventions) and splits the goal into children.

  2. Work spreads out

    Children are workers, checks, approval gates or sub-leads that split further, as deep as you allow.

  3. Workers build in parallel

    Each worker gets its own git worktree and branch, and ends every turn with a structured result.

  4. Every branch is merged

    One merge at a time onto the run's branch, then the checks run on the merged result.

  5. Conflicts get an agent

    A conflict or a failing check after a merge goes to the integrator, which resolves it.

  6. The result waits for you

    Everything lands on murm/<run>. Your own branch is untouched until you merge it.

The parts

Models decide. Code keeps it moving.

Leads

LLM agents whose only tools are orchestration: spawn, send, note, cancel, complete, fail, escalate. Each is a durable conversation that wakes when its children report.

Workers

Claude Code, Codex or Pi, in their own worktrees. Messages wait for the next turn, or interrupt the current one; the session resumes either way.

Checks and gates

Checks are shell commands that must pass on the merged result. Gates stop and wait for murm approve.

The supervisor

One process per run and the only writer of its event log. It starts every agent, routes every message, enforces the limits and merges every branch.

The integrator

A standing agent of the run. It is called only when a merge conflicts or a check fails after a merge.

You

The parent of the top-level work: answer questions, approve gates, cancel a subtree, or resume a stopped run, from any terminal.

Define the cast

You set the cast and the limits. Leads hire within them.

Built to survive

Kill it. Resume it.

The event log is the whole state of a run. murm resume records turns that finished while it was down, stops orphaned processes, resumes interrupted sessions, and never repeats a finished turn, check, spawn or merge. Leads recover through their own durable storage.

Portable traces

ATIF and Langfuse

Export any run as an ATIF trajectory with every agent nested under the lead that spawned it, or send it to Langfuse over OpenTelemetry. The deep run's trace passes Harbor's validator.

What's next

Watch the flock, and let it talk to others

Observe a run as it happens

Today you follow a run through murm status, its log, and traces exported afterwards. Next: a live view of the tree (who is working, waiting, merging or asking), the event stream sent to Langfuse while the run goes, and the numbers that matter at a glance: turns, tokens, merges and time per subtree.

A link with Comitia

Comitia is a durable message service for local agents. Linked to it, a run would mirror its events into a shared context that other tools and people can read, and agents Murmuration did not start, such as a Claude session you open yourself, could join the run as independent agents, take requests and report back.
